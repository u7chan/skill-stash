# 緊急点検チェックリスト

基準: IPA「不正アクセスによる漏えい等の事案を踏まえ、速やかに実施すべき対策等について」（2026-10-09）
https://www.ipa.go.jp/security/security-alert/2026/alert20261009.html

## A. 対象の棚卸し

- [ ] 外部公開する自社アプリ、API、管理画面、公開エンドポイントを列挙したか
- [ ] 各資産の責任部署、運用者、公開経路、認証方式、構成要素、関連データを記録したか
- [ ] SaaS、クラウド、VPN、リモートアクセス、IdPなどを部署単位まで確認したか
- [ ] 各サービスで確認できる監査ログ、保存期間、確認権限、調査担当者を把握したか
- [ ] 利用者側では見られず、提供者への照会が必要なログを特定したか

## B. ログの精査

- [ ] 直近1か月を起点に調べ、必要に応じて3か月等に範囲を拡張したか
- [ ] HTTP 4xx/5xx、認証失敗、WAF/リバースプロキシ、アプリ、監査ログの急増を確認したか
- [ ] 送信元IP/地域、利用時間帯、端末、User-Agent等に平時との差がないか
- [ ] 異常なログイン成功、管理操作、設定変更、APIキー発行等を確認したか
- [ ] 大量アクセス、データエクスポート、通常と異なるダウンロードを確認したか
- [ ] 比較対象期間・時刻帯・正当な運用変更を明記したか
- [ ] ログ欠損や未収集イベントを「未確認」と記録したか

## C. アカウント・権限

- [ ] 管理台帳/IdPとの照合で、未承認の新規アカウントがないか
- [ ] 退職者・停止済みアカウントが再有効化されていないか
- [ ] 管理者権限の新規付与、MFA設定変更、認証方式変更が正当か
- [ ] 不審な変更の実施者・日時・操作ログを追跡できるか

## D. 脆弱性・データ

- [ ] 外部公開アプリと構成要素のバージョン、未適用パッチ、該当アドバイザリを確認したか
- [ ] 修正の優先度・担当者・実施計画・承認要否を整理したか
- [ ] 保有データの種類・保存場所・保存必要性・アクセス権を確認したか
- [ ] 不要データの削減、暗号化、ログ保持、MFA、最小権限などの改善事項を抽出したか

## E. 異常検知時

- [ ] インシデント担当者と専門ベンダーへのエスカレーションを提案したか
- [ ] 証跡保全、漏えい可能性、影響サービス・対象者・時系列を整理したか
- [ ] 社内規程・法令・契約に基づく通知要否の確認担当を明確にしたか
- [ ] 変更・対外連絡は承認された対応手順に沿っているか

注: 上記の HTTP ステータスやデータ取得などの具体例は、IPAの注意喚起を実務に展開した追加観点。検知の閾値は環境に合わせて設計する。
