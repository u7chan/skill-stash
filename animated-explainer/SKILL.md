# Animated Explainer

依頼された題材を、ブラウザで再生できる単体のHTMLにする。縦型（9:16）の画面にタイトル、図、キャプションを配置し、本文を理解するのに役立つ場合に数値やコードを添える。画面は幅に合わせて拡大縮小する。

1. 何を理解できれば説明が完了するかを一文にする。対象の資料やコードがある場合は、実際の処理や用語を確認する。
2. 題材に合う順を選ぶ。処理なら「入力 → 変化 → 結果」、比較なら「同じ条件 → 違い → 結果」、構造なら「全体 → 部分 → つながり」を出発点にする。結論に必要な要素から順に出す。
3. 各シーンで伝えることを一つに絞る。図の出現、線上の移動、状態ラベルの変化など、キャプションの内容が目で追える変化を選ぶ。待ち時間は読む量に合わせる。短い説明では全体で15〜25秒を目安にする。
4. 変化の意味に合う演出を選ぶ。同じ動きを続けると単調になるので、シーンの意味が変わるところで変える。

   | 伝えること | `effect` |
   | --- | --- |
   | 次の段階へ進む | `rise` |
   | 前提・前の段階から入る | `drop` |
   | 左右の比較・分岐 | `left` / `right` |
   | 状態の変化を強調する | `pop` |
   | 全体から細部へ寄る | `zoom` |
   | 補足だけを差し替える | `fade` |

5. [入力形式](references/config.md)を参照して題材ごとの `content.json` を作る。数値が例示なら図やキャプションに明記する。`code` はコードの解説が要るシーンだけに置き、根拠になる行に絞る。擬似コードにはその旨を添える。
6. `python <スキルのディレクトリ>/scripts/build.py content.json <出力先>.html` で生成する。見た目の指定があれば独立した `theme.json` を用意し、コマンドに `--theme theme.json` を追加する。配布するHTMLには設定とプレイヤーが含まれる。
7. 可能ならブラウザで最初から最後まで確認する。図とキャプションが一致するか、画面上で文字や線が重ならないか、再生・一時停止・再開・シーン移動・最初からの再生が働くかを確認し、HTMLを渡す。スペースキーと左右キーでも同じ操作ができる。
