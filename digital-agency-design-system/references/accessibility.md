# アクセシビリティ要件

DADS は JIS X 8341-3:2016 / WCAG 2.2 への適合を前提にしている。ここには**実装で抜けやすい項目**だけを、判定可能な形で列挙する。`scripts/check-page.py` はこのうち機械判定できるものを検査する。

## 必須（破ると DADS 準拠にならない）

### フォーカスインジケーター

`:focus-visible` で **黒 4px のアウトライン + 2px のオフセット + 黄（`--color-primitive-yellow-300`）2px の内側リング**を表示する。`dads-global.css` に実装済みなので、上書き・削除しない。

```css
/* dads-global.css に入っている実装（変更禁止） */
:focus-visible {
  outline: calc(4 / 16 * 1rem) solid var(--color-neutral-black);
  outline-offset: calc(2 / 16 * 1rem);
  border-radius: calc(4 / 16 * 1rem);
  box-shadow: 0 0 0 calc(2 / 16 * 1rem) var(--color-primitive-yellow-300);
}
```

- `outline: none` / `outline: 0` を代替表示なしで書かない。
- 親要素に `overflow: hidden` を付けてフォーカスリングを切らない。
- 複合ウィジェットには `dads-u-focus-within-outline` を使う。

### コントラスト比

- テキスト: 背景に対して **4.5:1 以上**（大きい文字でも、本文は 16px 以上なので 4.5:1 を基準にする）。
- 非テキスト（アイコン・枠線・ディバイダー・ボタン面・入力欄の境界）: 隣接する背景に対して **3:1 以上**。
- 塗りボタンのラベルは**塗り色に対して** 4.5:1 以上。アウトラインボタンは枠線が背景に対して 3:1 以上。

### 色だけに依存しない

- エラー、必須、選択状態、ボタンの重要度を色の違いだけで示さない。
- プライマリーは塗り、セカンダリーはアウトラインと**形状も変える**。
- エラーは「色 + エラーテキスト + アイコン」の 3 点で示す。

### ターゲットサイズ

| 対象 | 最小 |
| --- | --- |
| アイコン単体のボタン | **44×44 CSS px** |
| リンクテキスト（インライン） | 24×24 CSS px（高さが足りなければ上下 4px 以上の余白で担保） |

`dads-button` の `xs` / `sm` は主要操作に使わない。

### フォーム

- すべての入力に `<label for>` でラベルを結びつける。`aria-label` は最終手段。
- `placeholder` を入力条件の説明に使わない。条件・例はサポートテキストに書く。
- `maxlength` を使わない。最大長はサポートテキストで示し、超過はサーバー側で検証してエラーテキストに文字数を出す。
- コピー＆ペーストを無効化しない（`oncopy` / `onpaste` を握りつぶさない）。
- `disabled` / `readonly` を安易に使わない。無効なコントロールはタブフォーカスで到達できず、なぜ操作できないかが伝わらない。確認画面では読み取り専用フィールドではなく地の文で表示する。
- エラー状態は `aria-invalid="true"` + `aria-describedby="<error-id> <support-id>"`。エラーテキストの ID を先に書く（読み上げ順 = 記述順）。
- エラー発生時はエラーにフォーカスを移すか、`role="alert"` で通知する。エラー要約を置く場合は各項目へリンクする。
- 必須は `data-required="true"`。項目名だけでなく必須であることもラベルに含める。

### 表

- セル結合を使わない。表を分割するか、セル内を構造化文章にして 1 行 1 レコードを保つ。
- `<caption>` で表の内容を示す。列見出しは `<th scope="col">`、行見出しは `<th scope="row">`。
- 表全体は `.dads-table` で包み、横スクロール時はシャドウで続きがあることを示す。

### アイコンと画像

- ラベル併記のアイコンは `aria-hidden="true"`（インライン SVG）/ `alt=""`（`<img>`）。`aria-label` を付けない。
- アイコン単体で使う場合は、本来のラベルを代替テキストにし、44×44 CSS px を確保する。
- リンクのアイコンはリンクのクリック領域に含める（別の `<a>` にしない）。
- 意味のある画像には内容を説明する `alt` を付ける。

### 文書構造

- `<html lang="ja">`、`<title>`、viewport meta を必ず置く。
- `<h1>` は 1 つ。見出しレベルを飛ばさない。
- `header` / `main` / `footer` / `nav` のランドマークを使う。`<nav>` が複数ある場合は `aria-label`（または `aria-labelledby`）で区別する。
- スキップリンク（本文へ移動）を本文の先頭に置く。
- リンクテキストだけで目的が分かるようにする。「ここ」「こちら」「もっと詳しく」のみは不可。

### レイアウト

- リキッドレイアウトにする。固定幅レイアウトにしない。
- 200% ズーム・320 CSS px 幅で水平スクロールが不要になるようにする。
- `order` / `grid-placement` は視覚的な並び替え専用。DOM 順・読み上げ順・フォーカス順は変えられないため、視覚順と論理順を一致させる。

## 強制カラーモード

Windows のハイコントラストモード等では影やオーバーレイシェードの表現が無効になる。

- 高さを持つ要素には**必ずボーダーを付ける**（透明でもよい）。境界が消えないようにする。
- 無効状態は `@media (forced-colors: active)` で `GrayText` 等のシステム色に落とす（`dads-button` 等は実装済み）。
- アイコンは単色 `currentColor` で描く。多色や背景画像に依存しない。

## 実装チェックの流れ

1. `python3 scripts/check-page.py <file>` で機械判定する（ERROR を 0 にする）。
2. キーボードだけで操作する: Tab で全操作要素に到達 → フォーカスリングが見える → Enter / Space で操作できる。
3. ブラウザのズーム 200%、幅 320px で表示を確認する。
4. 文字サイズを 200% にしてもレイアウトが破綻しないことを確認する。
5. スクリーンリーダー（NVDA / VoiceOver）で見出し・フォーム・表の読み上げを確認する。
