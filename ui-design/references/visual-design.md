# ビジュアルデザイン

## 情報設計・レイアウト

- 主要操作と補助操作を区別し、関連情報を近接させ、無関係な情報を分離する。
- 同じ情報を不必要に繰り返さず、内部実装の構造をそのままUIに露出しない。
- 整列と余白で構造を表現し、不要なコンテナを増やさない。
- 用途に合う密度を保ち、空間を埋めるための要素を追加しない。
- 操作要素の位置を不必要に変化させない。

## 文字・色

- 文字サイズとウェイトは情報の重要度に対応させ、種類を増やしすぎない。
- 本文の行間と可読性を確保し、補助情報を過度に小さく薄くしない。
- 既存フォントを合理的な理由なく変更しない。日本語・英数字の混在、数値の桁揃えを確認する。
- 色には意味を持たせ、アクセントを濫用しない。状態色を一貫させ、色だけで意味を伝えない。
- コントラストを確保し、グラデーションや発光を安易に使わない。

## コンポーネント・文言

- 同じ役割には同じ形状と操作方法を使う。主要操作と補助操作を区別する。
- ボタンとリンクの役割を混同せず、操作可能な要素は認識できるようにする。
- アイコンは意味の伝達に使い、アイコンのみの操作にはアクセシブルな名前を付ける。
- 不要な独自UIを作らない。
- 必要な情報だけ表示し、内部用語や自明な説明、見出しと説明の重複を避ける。
- 操作ラベルは具体的な動作を示し、エラーは可能な範囲で原因と対応方法を示す。

## モーション

状態変化、操作フィードバック、要素間の関係、視線誘導に必要な場合だけ使う。装飾目的の常時アニメーションや頻繁な操作の遅延を避け、モーション軽減設定を尊重する。

## アクセシビリティ

Web UIはWCAG 2.2 AAを基本目標とし、プロジェクト要件があれば従う。各基準の適用条件・例外を考慮する。

- 通常文字4.5:1、大きな文字3:1、必要な非テキスト要素3:1以上のコントラストを原則とする。
- キーボードで主要操作が可能で、フォーカスが視認でき固定UIなどに完全に隠れない。
- 操作領域は原則24×24 CSS px以上（基準の間隔等の例外を考慮）。タッチ操作に十分な領域と間隔を確保する。
- セマンティックHTML、意味のある読み上げ順序、拡大時の情報・操作の維持を確認する。

## アンチパターン

合理的な目的がない限り避ける。特定の色・フォント・形状を全面禁止しない。

- 装飾: 紫・青のグラデーションの濫用、過剰な発光・影・ぼかし・角丸・ピル型、無意味なガラス表現、背景模様、装飾アイコン。
- レイアウト: 何でもカード化、カードやボーダーの入れ子、同じカードの無意味な反復、全面中央揃え、過剰な余白、用途に合わないダッシュボード。
- 情報: 不要な補助見出し、自明な説明、ラベル・バッジの重複、意味のないAI・NEW・Beta、架空の統計・評価、空間を埋めるダミー情報、装飾目的の大文字・等幅フォント。
- 操作: 頻繁な操作を不要なメニューに隠す、不要な確認、意味不明なアイコン、演出による遅延、ホバーだけに依存する重要操作。
- 実装: 不要なライブラリ、既存コンポーネントの再実装、同じ意味のスタイルの個別定義、不要なラッパー、固定座標だけで成立するレイアウト。
