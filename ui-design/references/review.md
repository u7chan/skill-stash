# ビジュアルレビュー

利用者視点で実際の画面を評価し、実装者の意図や作業量を評価基準にしない。

## 証拠

可能な限りブラウザで実際に表示・操作し、スクリーンショット、変更前後、対象画面サイズ、必要な状態を確認する。コードで分かる問題と描画が必要な問題を区別する。

可能なら別エージェントまたは独立したコンテキストで評価する。画面の目的、対象ユーザー、主要ユースケース、規約、画面画像を渡し、実装者の自己評価や正当化は渡さない。独立環境がなければ同じエージェントで評価してよいが、独立レビューと称さない。

## 観点

- 理解性: 初見で目的、主要操作、優先順位、文言が理解できるか。
- 視覚品質: 余白、整列、文字、密度、色の意味、不要な装飾、既存UIとの調和、アンチパターン。
- 操作性: 主要操作の完了、操作可能性、状態と結果、誤操作防止、エラーからの回復。
- レスポンシブ: 意図しない横スクロール、重なり、画面外の操作、固定UIによる妨害、中間幅での変化。
- 状態: 変更に関連する通常、ローディング、空、エラー、無効、長文・長いファイル名、データ量、フォーカス・選択。
- アクセシビリティ: コントラスト、キーボード、フォーカス、操作領域、アクセシブルな名前、色だけに依存しない表現。

画像から判定できない事項はDOMや操作結果等で確認する。

## 重要度

- P0: 主要操作を完了できない。
- P1: 操作性・理解性を大きく阻害する。
- P2: 一貫性・視認性を低下させる。
- P3: 軽微な改善案・好みによる提案。

好みを重大な問題として扱わない。

## 結果

各指摘に重要度、対象画面・要素、観測した問題、利用者への影響、改善案を含める。曖昧な形容詞のみの指摘を避ける。問題がなければ無理に指摘を作らず、未確認事項を明示する。
